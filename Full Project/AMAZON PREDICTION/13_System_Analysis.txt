SYSTEM ANALYSIS (Refined and Formatted)
=====================================

13.1 Introduction
-----------------
This section provides a detailed analysis of the developed "Amazon Sales Analysis and Prediction System". It serves as a comprehensive evaluation of the system's operational context, addressing the shift from manual legacy processes to a modern, automated Machine Learning workflow.

13.2 Problem Analysis
---------------------
13.2.1 Current Operational Challenges
*   **Manual Dependency:** The previous workflow relied heavily on manual data aggregation from Excel files (`grocery_sales_data.xlsx`, `Amazon_Sales_Report.csv`), leading to substantial latency in decision-making.
*   **Data Fragmentation:** Sales data for different verticals (Dress, Electronics, Grocery) existed in disparate formats, making unified reporting difficult.
*   **Scalability Bottlenecks:** Legacy tools (Excel) struggled with datasets exceeding 100k records, causing frequent crashes and data integrity issues.

13.2.2 Business Impact
*   **Financial:** Delayed pricing adjustments due to slow reporting resulted in lost revenue opportunities during peak seasons.
*   **Operational:** Significant man-hours were wasted on repetitive data cleaning rather than strategic analysis.

13.3 Proposed Solution: Flask + ML Architecture
-----------------------------------------------
13.3.1 Solution Overview
The new system is a centralized Web Application (`app.py`) that integrates:
1.  **Data Processing Layer:** Automated ingestion and cleaning of raw CSVs using Pandas.
2.  **Intelligence Layer:** Pre-trained Random Forest models (`.pkl` artifacts) for robust sales forecasting.
3.  **Presentation Layer:** A lightweight, responsive HTML frontend (Flask Templates) for end-user interaction.

13.3.2 Component Analysis

A. Data Management (Pandas/Joblib)
*   **Function:** Standardizes input data and handles missing values automatically (e.g., imputation logic in `train_dress_model.py`).
*   **Benefit:** Ensures that the model always receives valid, normalized data, reducing prediction errors.

B. Machine Learning Engine (Scikit-Learn)
*   **Function:** Utilizes Random Forest Regressors to capture non-linear relationships between variables like `Category`, `Year`, and `State`.
*   **Benefit:** Provides high-accuracy predictions (R² > 0.85) instantly, replacing "gut-feeling" estimates.

C. User Interface (HTML5/CSS3)
*   **Function:** Simple, form-based interfaces (`electronics.html`, `dress.html`) that abstract away the complex ML logic.
*   **Benefit:** democratizes access to advanced analytics; non-technical sales managers can generate predictions in seconds.

13.4 Feasibility Confirmation
-----------------------------
*   **Technical:** Validated. The system runs efficiently on standard hardware without specialized GPUs.
*   **Economic:** Cost-effective. Utilizes 100% open-source technologies (Python, Flask, Scikit-learn), eliminating licensing fees.
*   **Operational:** Accessible. The web-based nature ensures easy deployment and access for all stakeholders.
